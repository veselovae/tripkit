# TripKit

Веб-приложение для планирования путешествий: поездки, чек-листы, транспорт и проживание в одном месте.

**[Открыть TripKit →](https://tripkit-pi.vercel.app/)**

Пет-проект на Nuxt, Vue и TypeScript с авторизацией и хранением данных в Appwrite. Интерфейс доступен на русском и английском языках. Для работы с поездками нужно создать аккаунт.

## Возможности

- **Поездки.** Создание и редактирование: название, направление, даты и заметки.
- **Обзор поездки.** Прогресс подготовки, ближайший транспорт, информация о проживании и быстрые переходы к разделам.
- **Чек-листы.** Группы с иконками, редактирование пунктов, отметки о выполнении и сортировка перетаскиванием.
- **Готовый чек-лист.** Шаблон с документами, электроникой, одеждой и делами перед поездкой. Создаётся на выбранном языке.
- **Транспорт.** Самолёты, поезда, автобусы, паромы и автомобили: маршрут, время, перевозчик, номер бронирования, место и заметки.
- **Проживание.** Даты заезда и выезда, адрес, контакты, сайт и номер бронирования.
- **Авторизация.** Регистрация, вход по почте и паролю, выход из аккаунта.
- **Локализация.** Переключение между RU и EN с сохранением выбора и форматированием дат.
- **Состояния интерфейса.** Скелетоны загрузки, пустые состояния, уведомления, повтор загрузки и подтверждение удаления.

Проект развивается. Хранение документов и полноценные настройки аккаунта пока не реализованы.

## Как устроен проект

Страницы обращаются к серверным маршрутам Nuxt через composables. Сервер проверяет входные данные и пользователя, затем выполняет запросы к Appwrite от имени его сессии. Сессия хранится в HTTP-only cookie, а создаваемым записям назначаются права владельца.

```text
app/
├── components/         # Общие компоненты, поездки, чек-листы и бронирования
├── composables/        # Авторизация и обращения к API
├── layouts/            # Основной макет и страницы авторизации
├── middleware/         # Проверка доступа к страницам
├── pages/              # Страницы приложения
└── utils/              # Форматирование дат, типы транспорта и иконки
server/
├── api/                # API авторизации, поездок и связанных записей
├── lib/                # Клиенты Appwrite
├── middleware/         # Получение текущего пользователя
└── utils/              # Проверки доступа и преобразование данных
shared/
├── data/               # Стартовый шаблон чек-листа
├── schemas/            # Схемы Zod
└── types/              # Общие TypeScript-типы
i18n/
├── i18n.config.ts       # Конфигурация переводов
└── locales/            # Словари en.json и ru.json
scripts/                # Проверка словарей локализации
```

## Локальный запуск

Понадобятся Node.js 22.19+ в ветке 22.x либо 24.11+ в ветке 24.x, npm и проект Appwrite с поддержкой TablesDB.

### 1. Установить зависимости

```bash
git clone https://github.com/veselovae/tripkit.git
cd tripkit
npm ci
```

### 2. Подготовить Appwrite

В репозитории пока нет миграций или скрипта создания базы. Для самостоятельного запуска нужно настроить проект Appwrite, авторизацию по почте и паролю, серверный API-ключ для создания сессий, базу данных и пять таблиц:

| Таблица | Содержимое | Модель данных |
| --- | --- | --- |
| Поездки | Направление, даты, описание, владелец | [Trip](shared/types/trip.ts) |
| Группы чек-листа | Название, иконка, поездка, порядок | [ChecklistGroup](shared/types/checklist.ts) |
| Пункты чек-листа | Группа, текст, статус выполнения, порядок | [ChecklistItem](shared/types/checklist.ts) |
| Транспорт | Маршрут, даты, реквизиты бронирования | [Transport](shared/types/transport.ts) |
| Проживание | Объект размещения, даты, контакты | [Accommodation](shared/types/accommodation.ts) |

Названия и ID таблиц можно выбрать самостоятельно. Их ID задаются в переменных окружения. Колонки должны соответствовать данным, которые записывают [серверные обработчики](server/api), а ограничения строк — [схемам валидации](shared/schemas). Поля `id`, `createdAt` и `updatedAt` в моделях формируются из системных полей Appwrite; отдельные колонки для них не нужны.

Включите права на уровне строк и разрешите авторизованным пользователям создание записей. Чтение, изменение и удаление конкретных записей приложение разрешает их владельцам. Настройте индексы для используемых в обработчиках фильтров и сортировок: `ownerId`, `tripId`, `groupId`, `sortOrder` и полей дат соответствующих таблиц.

### 3. Заполнить переменные окружения

Создайте `.env` в корне проекта по образцу [.env.example](.env.example):

```dotenv
NUXT_PUBLIC_APPWRITE_ENDPOINT=https://<REGION>.cloud.appwrite.io/v1
NUXT_PUBLIC_APPWRITE_PROJECT_ID=

NUXT_APPWRITE_API_KEY=
NUXT_APPWRITE_DATABASE_ID=
NUXT_APPWRITE_TRIPS_TABLE_ID=
NUXT_APPWRITE_CHECKLIST_GROUPS_TABLE_ID=
NUXT_APPWRITE_CHECKLIST_ITEMS_TABLE_ID=
NUXT_APPWRITE_TRANSPORT_TABLE_ID=
NUXT_APPWRITE_ACCOMMODATIONS_TABLE_ID=
```

Endpoint скопируйте из настроек своего проекта Appwrite. API-ключ используется только на сервере: он не должен попадать в переменные с префиксом `NUXT_PUBLIC_` или в Git.

### 4. Запустить приложение

```bash
npm run dev
```

Откройте `http://localhost:3000`, зарегистрируйтесь и создайте первую поездку.

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Сервер разработки |
| `npm run build` | Сборка приложения для развёртывания |
| `npm run preview` | Локальный просмотр готовой сборки |
| `npm run check:i18n` | Проверка ключей, параметров и корректности переводов |

При развёртывании задайте переменные из `.env.example` в настройках окружения хостинга. Для авторизации в production нужен HTTPS: сессионная cookie использует флаг `Secure`.

## Локализация

Переводы находятся в [en.json](i18n/locales/en.json) и [ru.json](i18n/locales/ru.json). При добавлении текста интерфейса добавляйте один и тот же ключ в оба словаря и запускайте:

```bash
npm run check:i18n
```

Переключение языка меняет интерфейс и формат дат. Пользовательские названия поездок, заметки и уже созданные пункты чек-листа сохраняются без изменений.
